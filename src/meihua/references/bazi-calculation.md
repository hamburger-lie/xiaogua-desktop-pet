# 八字排盘统一口径

本文件规定“每日一瓜”从出生信息生成四柱、大运与流年结构时采用的唯一默认口径。它解决可复算性，不声称某一流派获得现代实证验证。

## 必要输入

- 出生公历年月日和尽可能准确的当地钟表时间。
- 出生城市或 IANA 时区。
- 出生地经度；真太阳时只需要经度，东经为正、西经为负。
- 出生时间若只是约数，记录可能误差为正负多少分钟；不要把“约八点”当成精确到分钟。
- 只有需要按传统规则排大运时，才询问用户性别；用户也可以直接指定顺排或逆排。

不要索取身份证号、证件照片、医院证明或精确住址。城市级位置已足够。出生时间只用于本次排盘，不反推隐私事实。

## 统一排盘口径

1. **公历和时区**：使用 IANA 时区处理当地法定时间及历史夏令时，支持 1901—2099 年。夏令时跳转造成的不存在时间直接拒绝；回拨造成的重复时间必须由输入中的 UTC 偏移明确选择，不能静默猜测。
2. **年柱**：以立春的实际时刻为界，不以公历元旦或农历正月初一换年。
3. **月柱**：以立春、惊蛰、清明、立夏、芒种、小暑、立秋、白露、寒露、立冬、大雪、小寒十二个“节”为界，不按农历初一换月。
4. **太阳位置**：用太阳视黄经判断节气。香港天文台说明二十四节气把黄道分成每段 15°，立春为 315°；本引擎据此每隔 30°取一个月令交界。
5. **时钟口径**：默认采用真太阳时。先按出生地经度与时区中央经线校正，再加入均时差；同时保留法定时间。均时差和太阳位置公式采用 NOAA 所述 Meeus 近似思路。
6. **日界**：默认子初换日，即 23:00 起进入下一干支日；用户可以指定 00:00 换日。出生落在 23 时段时，必须输出两种日界对照盘，不替用户掩盖分歧。
7. **边界处理**：用户提供出生时间误差时，以实际时刻加减该误差生成区间上下限；只有上下限得到不同四柱时才列候选盘。未提供误差而距节气交界不超过 15 分钟时，只提示核对记录精度，不虚构固定的“前后两小时”候选。真太阳时校正若跨越时辰或日期，仍输出法定时间对照盘。这些是同一输入的规则敏感性检查，不是重新测算。

运行：

```bash
python engines/cast_bazi.py \
  --datetime 1990-05-12T08:30:00 \
  --timezone Asia/Shanghai \
  --longitude 113.2644
```

只想按法定时间排盘时，追加 `--clock-mode legal`。用户明确选择 00:00 换日时，追加 `--day-boundary midnight`。

出生时间可能有正负 20 分钟误差时：

```bash
python engines/cast_bazi.py \
  --datetime 1990-05-12T08:30:00 \
  --timezone Asia/Shanghai \
  --longitude 113.2644 \
  --uncertainty-minutes 20
```

## 大运口径

需要大运时使用以下统一规则：

- 年干为阳且用户选择男，或年干为阴且用户选择女：顺排。
- 年干为阴且用户选择男，或年干为阳且用户选择女：逆排。
- 顺排从出生时刻数到下一个“节”；逆排数到上一个“节”。
- 三日折一年，大运每十年一柱，从月柱顺排或逆排。
- 用户不愿提供性别时，可直接指定 `--direction forward` 或 `--direction reverse`；两者都没有时，不自动排大运。

示例：

```bash
python engines/cast_bazi.py \
  --datetime 1990-05-12T08:30:00 \
  --timezone Asia/Shanghai \
  --longitude 113.2644 \
  --sex male
```

《命理探源》的“推大运法”明确记载顺逆、数至前后节及“三日为一岁”的口径。它说明传统规则来源，不证明大运具有客观预测效度。

## 流年口径

- 流年同样以当年立春为起点。
- 引擎只计算流年干支、流年天干相对日主的十神，以及流年地支与原局的六合、六冲。
- 不因为出现合、冲或某十神，就断言结婚、离职、发财、患病等具体事件。
- 需要某一整段流年周期时追加 `--target-year 2027`，含义是“2027 年立春起至 2028 年立春前”，不是自然年 1 月 1 日至 12 月 31 日。
- 用户问的是某个具体公历日期时，使用 `--target-date 2027-01-20`。引擎按目标地点的实际立春时刻判定归属；例如 2027 年立春前的日期仍属于丙午流年。

## 解释框架

排盘后把四柱交给：

```bash
python engines/analyze_bazi.py --pillars <年柱> <月柱> <日柱> <时柱>
```

解释顺序固定为：

1. 日主与月令主气。
2. 日主在地支是否见同五行根，不以根数直接判强弱。
3. 与问题直接相关的十神。
4. 明确出现的合、冲、三合。
5. 若用户要求，再把大运或流年当作时间背景叠加。

不自动取喜用神，不以五行数量判旺衰，不使用“缺什么补什么”。格局、调候、病药只能作为人工解释检查项：必须同时检查月令、透干、通根、制化和寒暖燥湿，并使用条件性语言。
